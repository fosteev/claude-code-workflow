# claude-code-workflow

Мой цикл работы с Claude Code и скиллы, которыми пользуюсь каждый день. Без привязки к
конкретным проектам — бери, выкидывай лишнее, подкручивай под себя.

## Идея в двух строках

Сильная модель (Opus) тратится на **суждение** — анализ, решения, ревью. **Печатание
кода** по готовому плану уходит дешёвому исполнителю (Sonnet-субагент). Ничего важного
не живёт только в чате: планы, промты и статусы — в файлах.

```
вход → 1. анализ → 2. маршрут → 3. артефакт → 4. исполнение → 5. приёмка → 6. закрытие
                        │                          ▲              │
            ┌───────────┼───────────┐              └──────────────┘
          сам        промт →      roadmap →        (цикл по этапам L)
          (S)      исполнитель   этапы → исполнители
                      (M)            (L)
```

| Размер | Ясно | Неясно |
|---|---|---|
| **S** (до часа, ≤3 файлов) | Opus делает сам | Сам, но сначала 3 строки: решение, DoD, что не трогаю |
| **M** (до полудня) | Промт → Sonnet-исполнитель → приёмка | Вопросы пользователю → решения → промт |
| **L** (несколько сессий/репо) | Roadmap, каждый этап = промт | `/devil` → roadmap с вопросами → решения |

Важно: **не каждый запрос — полный цикл.** Голая ссылка или вопрос — ответ и «делаем?».
Мелочь — сделать сразу. Цикл plan → исполнитель → plan-review — только для задач больше
часа и по явной просьбе.

Подробно — [`WORKFLOW.md`](WORKFLOW.md).

## Что в репо

| Файл | Что это |
|---|---|
| [`WORKFLOW.md`](WORKFLOW.md) | Алгоритм: ворота, классы задач, маршруты, шаблон промта исполнителю |
| [`CLAUDE.example.md`](CLAUDE.example.md) | Мой глобальный `~/.claude/CLAUDE.md`: стиль, экономия контекста, делегирование, «позиция» (не поддакивать) |
| `skills/` | Скиллы ниже |

### Скиллы

| Скилл | Шаг цикла | Зачем |
|---|---|---|
| [`plan`](skills/plan/SKILL.md) | 1–3 | Анализ задачи, класс S/M/L × ясно/неясно, маршрут, промт исполнителю, запуск субагента |
| [`plan-review`](skills/plan-review/SKILL.md) | 5 | Приёмка работы исполнителя: план ↔ факт, починка, проверки, коммит/push, чеклист «проверь руками» |
| [`roadmap`](skills/roadmap/SKILL.md) | 3 (L) | Roadmap в md-файле: этапы с чекбоксами, «готово, когда», модель на этап, промты сессий |
| [`roadmap-run`](skills/roadmap-run/SKILL.md) | 4–5 подряд | Автопилот по roadmap: исполнитель → Opus-приёмка → коммит на каждый этап; ждёт сброса лимитов сам |
| [`continue`](skills/continue/SKILL.md) | 6 | Остаться в чате / `/compact` / новый чат с готовым промтом — по токенам и релевантности |
| [`devil`](skills/devil/SKILL.md) | 1 | Адвокат дьявола: разнести идею до реализации, предложить альтернативы |
| [`review-local`](skills/review-local/SKILL.md) | 5 | Ревью незакоммиченных изменений через локальный git |
| [`figma`](skills/figma/SKILL.md) | — | Рендер нода Figma в PNG + JSON со стилями через REST API (нужен `FIGMA_TOKEN`) |

Главные — `plan` → `plan-review` → `continue`. В `CLAUDE.md` прописано, что Claude
зовёт их **сам** по ситуации, а не ждёт команды.

## Установка

```sh
git clone https://github.com/fosteev/claude-code-workflow.git
cd claude-code-workflow

# скиллы
mkdir -p ~/.claude/skills
cp -R skills/* ~/.claude/skills/

# алгоритм (скиллы ссылаются на ~/.claude/WORKFLOW.md)
cp WORKFLOW.md ~/.claude/

# глобальные правила — НЕ перезаписывай свой CLAUDE.md вслепую, лучше влей нужное руками
cat CLAUDE.example.md
```

## Нюансы

- Всё на русском — скиллы работают и так, модель понимает. Переводить не обязательно.
- Скиллы ссылаются на «корневой `CLAUDE.md` воркспейса» — у меня это файл в папке со
  всеми проектами с таблицей «папка → проект → трекер». Без него тоже работает.
- `roadmap-run/limits.mjs` берёт OAuth-токен Claude Code (`~/.claude/.credentials.json`
  или macOS Keychain) и ходит в **недокументированный** `api.anthropic.com/api/oauth/usage`,
  чтобы узнать заполнение 5-часового и недельного лимита. Токен никуда не печатает. Может
  сломаться в любой момент — тогда автопилот просто продолжает без прогноза.
- В `CLAUDE.example.md` есть правило «без `Co-Authored-By: Claude` в коммитах» — это
  вкусовщина, убери, если тебе подписи не мешают.
- Пороги контекста (120k мягкий / 200k жёсткий) — абсолютные, от размера окна не зависят:
  на 300k каждый ход дороже и модель фокусируется хуже, даже если окно 1M.
