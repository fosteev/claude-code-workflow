# Plan — анализ, маршрут, артефакт

Реализует шаги 1–3 алгоритма `~/.claude/WORKFLOW.md`. Роль: архитектор. Сильная
модель тратится на суждение — понять, решить, расписать; печатать по готовому плану
должна Sonnet-сессия. Результат скилла — вердикт маршрута и артефакт под него, не код
(исключение — маршрут S, там код и есть артефакт).

## Шаг 0. Вход

Задача из аргумента или разговора: ключ Jira, ссылка, текст, «продолжаем X». Определить
проект (ключ/путь → корневой `CLAUDE.md` воркспейса), прочитать доку проекта и его конвенции
(коммиты, roadmap, проверки). Если задача уже начата — найти её roadmap и читать его,
а не чат. Задача не названа — спросить одной строкой.

## Шаг 1. Анализ — коротко, в чате

Четыре пункта, каждый 1–3 строки:

1. **Что просят + DoD.** Задача одной фразой; «готово» — команда или наблюдаемый факт.
   DoD без команды — не DoD.
2. **Разведка.** Точки входа `файл:строка`, что уже есть, что мешает, эталон для
   копирования, если найден. Больше трёх чтений или широкий grep — субагент Explore
   (`model: sonnet`), в чат только итог. Без разведки план — фантазия.
3. **Позиция.** Проблема / альтернатива первой строкой, если видна (правило «Позиция»
   в CLAUDE.md). Спорное или крупное — `/devil` до плана.
4. **Класс.** Две оси, назвать явно:
   - **Размер.** S — до часа, ≤ 3 файлов. M — до полудня, до ~10 файлов, одна сессия.
     L — несколько сессий или несколько репо.
   - **Суждение.** Ясно — все решения можно принять сейчас, эталон есть. Неясно —
     открытые вопросы к пользователю, незнакомый код, эталона нет.

## Шаг 2. Маршрут

| | Ясно | Неясно |
|---|---|---|
| **S** | Сам, здесь | Сам, здесь; сначала три строки: решение, DoD, что не трогаю |
| **M** | Промт → Sonnet-сессия | Открытые вопросы пользователю одним сообщением → решения → промт |
| **L** | Roadmap, каждый этап = промт | `/devil` → roadmap с открытыми вопросами → решения → как L/ясно |

**Всегда сам на сильной модели, любой размер:** security-sensitive код; миграции с
данными и raw SQL; транзакции и гонки; правки стейта без smoke-теста; новая вёрстка
без прототипа; всё, где план говорит «по аналогии», а аналогия неточная. Внутри L такой
этап помечается «opus», остальные идут исполнителю.

Вердикт — одной строкой: `Класс: M/ясно → промт для Sonnet-сессии` и почему в одну
фразу. Пограничные случаи (час-полтора, 4 файла) — в сторону S: промт стоит 10–15
минут и на мелочи не окупается.

## Шаг 3. Артефакт

- **S** — делать сразу, по правилу «Шум»: фрагменты вместо файлов, длинный вывод в
  лог. Итог 1–2 предложения. Если по ходу задача выросла в M — остановиться и вернуться
  к шагу 2, не дожимать в Opus.
- **Промт пишется один раз и живёт в файле.** Текст промта — самый дорогой output
  сильной модели; в чат и в `Agent` он не копируется. Для L — раздел «Промты» roadmap,
  для M — `docs/roadmaps/<ключ>-prompt.md` репо (нет такой конвенции — файл в
  скратчпаде, путь в чат). В чат — путь и три строки: задача, DoD, границы. Исполнителю
  — указатель: `Agent(subagent_type: "general-purpose", model: "sonnet",
  effort: "<из шапки промта: high|max>", run_in_background: true, prompt: "Прочитай промт в <путь>, раздел <N>, и выполни его
  дословно. Отчёт — последним сообщением, как сказано в промте.")`.
- **M** — промт по шаблону ниже в файл и **в том же ответе запуск исполнителя**.
  Пользователь видит путь и резюме и прервёт, если не согласен. Ждать «ок» не нужно —
  решения уже приняты в шаге 1–2; исключение — маршрут «неясно», где открытые вопросы
  ещё не отвечены.
- **L** — `/roadmap`: этапы с чекбоксами, «готово, когда», пометка сессии на этап
  (модель, effort, параллельность), промты сессий в разделе «Промты» файла. В чат —
  путь, этапы одной строкой каждый, резюме первого этапа и запуск его исполнителя.
  Параллельные этапы — несколько `Agent` в одном блоке; последовательные — следующий
  стартует из `/plan-review` предыдущего.
- **Пока исполнитель работает** — ничего не делать и не печатать: уведомление о
  завершении придёт само. Пришло — `Skill(plan-review)` с отчётом агента на входе,
  без команды пользователя. Ручная Sonnet-сессия вместо субагента — только
  если пользователь сказал, что хочет вести исполнителя сам.

### Шаблон промта исполнителю

Рассчитан на слабую модель: нулевая свобода в «что», все решения в тексте, читать
2–4 дока путями, точки входа названы, DoD и команды дословно, запреты явные.

```
Сессия <N> — <задача> · Модель: sonnet, effort: <high|max на этапе K> · <после сессии N-1 | параллельно с N>

Работаем в <абсолютный путь к репо>. Задача: <одной фразой>. <Что уже есть; доработка или стройка.>

Читай: <roadmap-файл, если есть>; <2–4 дока путями>. Правила репо: <путь к CLAUDE.md>.
Точки входа: <файл:строка — что там>. Эталон для копирования: <файл>.
Точки входа и эталоны проверены при планировании — не перечитывать их ради подтверждения,
открывать только фрагмент, который правишь.

Уже решено, не переспрашивать: <решения списком>.

Порядок:
1. <этап одной строкой>
2. …
Галочки в roadmap — по факту проверки, не «вроде сделал».

DoD: <дословно>. Проверка: <минимально достаточные команды — анализ/линт/тесты проекта;
полная сборка (apk/ipa/docker) только если тронуты зависимости, native или конфиги сборки>.

Не делать: <границы скоупа>; чужие незакоммиченные файлы не трогать; dev-процессы и
dev-миграции не запускать; «заодно улучшить» — нет. Вопрос, на который нет ответа в
промте, — в отчёт, не додумывать.

Не коммитить, не пушить, миграции не запускать — это сделает приёмка.
Последним сообщением — отчёт: сделано (файлы) / отклонения от плана / не проверено /
открытые вопросы. Отчёт — единственное, что увидит приёмка: без него работа потеряна.
```

Обязательные поля: директория, точки входа, «уже решено», DoD с командами, запреты,
формат отчёта. Каждая точка входа и каждый тип/класс в «уже решено» — открыты глазами
(хотя бы grep сигнатуры), а не взяты из пересказа Explore: исполнитель, наткнувшись на
«провайдер не в дереве», либо отступит от промта, либо додумает. Для ручной Sonnet-сессии вместо последнего абзаца — коммит по формату
репо, push после зелёных проверок и `/continue`. Промт без точек входа заставит исполнителя заново делать
разведку, за которую уже заплатили здесь.

### Модель и effort исполнителя

- **sonnet, high** — по умолчанию: код и контракт даны дословно, эталон есть.
- **sonnet, max на этапе K + ревью Opus** — один рискованный короткий этап: дешевле,
  чем Opus на всю сессию. Sonnet на max склонен перечитывать по кругу — если сессия
  буксует, это оно.
- **opus** — суждение по ходу неизбежно (список выше). Пометка у этапа, не у всей сессии.

Параллельные сессии — только когда разные репо, контракт зафиксирован в roadmap, нет
генерируемых артефактов и общих файлов между ними. Одно репо — всегда последовательно.

## Шаг 4. Ответ

Порядок: четыре пункта анализа → строка вердикта → артефакт (путь к файлу с промтом
или к roadmap + три строки резюме этапа) → вызов `Agent` с указателем на промт. Без пересказа
доков и без кода для маршрутов M/L. Дальше — тишина до отчёта агента, затем
`Skill(plan-review)`.
