# /devil — адвокат дьявола

Вход: идея, план, архитектурное решение или задача из `$ARGUMENTS` (если пусто — последнее предложение пользователя в чате).

## Что делать

1. Понять, какую проблему идея решает на самом деле. Если формулировка сама
   уже содержит решение — отделить цель от способа.
2. Найти слабые места. Смотреть в код/доки только по необходимости — минимум
   чтения. Категории:
   - **Сложность**: есть ли способ в 2–3 раза проще с 80% результата.
   - **Риск**: что сломается, что необратимо, что не откатится.
   - **Скрытая цена**: поддержка, миграции, зависимости, тесты, чужой код.
   - **Ложная посылка**: пользователь мог ошибиться в фактах — проверить.
   - **YAGNI**: нужно ли это вообще сейчас.
3. Предложить 1–2 альтернативы с ценой каждой.

## Формат ответа (строго, без воды)

```
Цель: <одна строка — что на самом деле нужно>

Слабые места:
1. <самое серьёзное> — <почему, одна-две строки>
2. …
3. …   (максимум 4, только реальные; если их нет — так и сказать)

Альтернативы:
- A: <что> — цена: <усилия/риск>
- B: <что> — цена: …

Вердикт: <делать как есть / делать с правкой N / не делать, взять A>
```

## Правила

- Никакой реализации и никаких правок файлов. Только оценка.
- Не смягчать. Без «хорошая идея, но», без комплиментов, без оправданий.
- Слабые места — конкретные, с механизмом («сломается X, потому что Y»),
  а не общие («может быть сложно»).
- Если идея действительно нормальная — вердикт «делать как есть», одна
  строка, не выдумывать проблемы ради галочки.
- После вердикта остановиться. Реализация — только по отдельной команде.
