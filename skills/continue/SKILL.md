# Session Triage — куда продолжать

Оценить текущую сессию и следующую задачу, вынести вердикт: **здесь / compact / новый чат**, и сразу выполнить подготовку к выбранному пути. Вердикт — один абзац с обоснованием, без эссе.

## Шаг 1. Определить следующую задачу

Из сообщения пользователя. Если задача не названа — спросить одной строкой, без этого триаж не имеет смысла.

## Шаг 2. Три вопроса к сессии

1. **Релевантность:** какая доля текущего разговора нужна для следующей задачи? Прямое продолжение той же задачи — высокая; новая фаза или тема — низкая. Если задача не названа, а текущая не закончена, следующая задача — та же самая: это продолжение, не новая фаза.
2. **Объём — числом, в абсолютных токенах.** Оценить заполнение контекста и **написать в вердикте явно** (`~110k`), чтобы человек поправил одним словом, если оценка промахнулась. Не считать «сколько файлов прочитано» и «насколько распух» — только токены. Пороги **абсолютные и от размера окна не зависят**: до 120k объём не аргумент; 120–200k — довод вместе с низкой релевантностью; от 200k — аргумент сам по себе. Причина: цена сессии = контекст × число ходов, и на 300k каждый ход стоит втрое дороже нормального при худшем фокусе модели; окно 1M это не отменяет. Картинки и скриншоты считаются в те же токены и стоят дороже всего.
3. **Что живёт только здесь.** Перечислить, что есть в этом разговоре и не легло на диск: незакоммиченный код, скрипты и пробы, гонявшиеся инлайном, решения без записи в доках, промежуточные числа. Непустой список — довод **остаться**, а не повод начать выгрузку: цена ухода — потеря этого состояния плюс холодный кэш и повторная разведка, и она взвешивается наравне с ценой длинного контекста.

## Шаг 3. Матрица вердикта

Две оси независимы, и смешивать их нельзя: «новая тема» сама по себе не повод уходить, «много токенов» сам по себе не повод тоже.

| | объём мал (до 120k) | объём велик (от 200k) |
|---|---|---|
| **та же задача, контекст нужен** | **Здесь.** Кэш тёплый, ничего не делать | **Новый чат** с промтом-продолжением (шаг 4); **/compact** — только если список из вопроса 3 непуст и выгрузить его дёшево нельзя. Предупредить, что summary с потерями |
| **новая тема, контекст не нужен** | **Здесь.** Уход стоит дороже, чем лишние токены | **Новый чат.** Перед этим — чеклист выгрузки (шаг 4) |

Между 120k и 200k решает релевантность: та же задача — здесь, новая тема — новый чат. От 200k «остаться» не вариант: если список из вопроса 3 непуст — выгрузить его по чеклисту шага 4 и уйти, это и есть цена продолжения.

Принцип: длинный контекст — это и цена, и качество: фокус модели в заполненном окне хуже, чем в свободном. Пороги — абсолютные тысячи, а не доли окна: большое окно позволяет доехать до 400k, но не делает это дешевле.

## Шаг 4. Чеклист выгрузки (перед «новый чат»)

Ничего ценного не должно жить только в чате:

- [ ] Незакоммиченные изменения → закоммитить (по правилам репо) **и запушить**. Unpushed-коммиты — тоже состояние «только здесь»; если push невозможен (нет доступа, ветка не для пуша) — сказать это явно в вердикте.
- [ ] Всё из списка «что живёт только здесь» (шаг 2, вопрос 3): пробы и скрипты, гонявшиеся инлайном, — в файл в репо или в скратчпад с путём в промте; промежуточные числа — в док.
- [ ] Решения и договорённости из разговора, которых нет в доках → дописать в доки проекта.
- [ ] Устойчивые факты/предпочтения → memory (не дублировать то, что уже записано в репо).
- [ ] **Самодостаточный промт для новой сессии.** Если в проекте есть конвенция — использовать её (например, раздел «Промт для сессии» в доке фазы roadmap): проверить, что промт существует и актуален, при необходимости обновить в доке — док остаётся источником правды.
- [ ] Если начинается фаза из roadmap — обновить её статус-баннер и индекс (например, баннер в доке фазы + таблица в `roadmap/README.md`).

Самодостаточный промт содержит: модель и effort, на которых его запускать (исполнение по плану — sonnet, план/ревью — opus); рабочую директорию; задачу одной фразой; список доков для чтения (пути); порядок работы; DoD и команды проверки; ссылки на правила проекта (CLAUDE.md); что обновить по завершении. Всё, что новая сессия не выведет из репо сама, — написать явно.

## Шаг 5. Сверка с roadmap

Перед вердиктом — независимо от него — свериться с роадмапом задачи, над которой шла сессия.

**Roadmap с чек-листами есть** (конвенция проекта: `docs/roadmap*`, `roadmap-*.md`, файл из скилла roadmap):

- Пройтись по чекбоксам и отметить `[x]` то, что реально закрыто в этой сессии. Закрыто = проверено (тест, команда, наблюдаемый факт), а не «вроде сделали».
- Посчитать остаток. Если он ноль — roadmap закрыт целиком: обновить статус-баннер (и индекс, если конвенция требует) и сказать об этом прямо.

**Roadmap нет** — сгенерировать его на месте по формату скилла roadmap из контекста сессии (что уже сделано — сразу отмеченными пунктами, что осталось — открытыми) и **предложить занести в файл**; в файл писать после согласия пользователя.

## Шаг 6. Вердикт и действие

Одним абзацем: вердикт, почему, и что сделано. В абзаце обязательно стоят обе оси числом и словом: заполнение контекста (`~110k`) и релевантность (та же задача / новая тема), — иначе человеку нечего поправить. Для /compact и нового чата — команды выполняет пользователь, не ассистент.

Следом — итог сверки из шага 5: какие пункты закрыты за эту сессию (списком) и сколько осталось (числом, по этапам). Если roadmap закрыт целиком — сказать это вместо остатка.

При вердикте «новый чат» — **обязательно привести сам промт последним элементом ответа, целиком, в fenced-блоке**, чтобы пользователю осталось только скопировать. Не отсылать «открой файл и скопируй оттуда»: промт берётся из дока проекта (или пишется на месте, если конвенции нет) и печатается в чат дословно; если правил его в доке — печатать уже обновлённую версию.
